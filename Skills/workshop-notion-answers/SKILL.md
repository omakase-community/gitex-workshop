# Find Answers in Notion

At entry, read [common behavior](../workshop-decide/references/common.md) and [connections](../workshop-decide/references/connections.md). The default starting experience is connecting Notion and investigating a useful question, rather than requesting screenshots or pasted pages. Honor an existing connection, an explicit example choice, supplied material, or a refusal to connect.

## Choose the question and scope

Offer the actual Notion connection path from the shared guide. Once connected, or when the user chooses examples, ask what project or customer question they want answered. Reuse a question already given. Examples can help an unsure participant: “What did we decide for this customer?” or “What still needs an answer before we can proceed?” Let their interest set the direction.

Before private content search, identify the selected page, project, or bounded set of pages. A connection makes pages accessible; it does not select the entire workspace for this exercise. When the user knows a project but not its page, agree to locate that project before expanding the search. Broaden scope conversationally if a relevant answer lies elsewhere.

For fictional examples, read [Kivo context](../workshop-decide/assets/kivo-company.txt) and [Harborline project pages](assets/notion-project-pages.txt). Introduce Alex's role and the frozen scenario date. The page IDs in that file are local source labels, not live Notion pages or evidence that a connection was made.

**Ready to investigate:** the user's question, source mode, and content scope are known. No extra intake is needed merely to fill a template.

## Follow the evidence

Treat search results as leads to relevant pages. Read the full relevant page content, including accessible child blocks or database records needed for the answer, and follow in-scope references. State access gaps when a referenced source cannot be read. A title or search snippet alone cannot establish a decision.

Compare the source dates, status, authorship, and recorded decisions. A recent edit does not automatically override an explicit agreement. Preserve meaningful conflicts and explain which evidence resolves them; distinguish older assumptions, proposed designs, confirmed commitments, and remaining questions. An unanswered question or missing completion record is uncertainty, not proof of rejection or non-completion.

Answer the chosen question first, with page links or IDs beside material claims. Separate source-backed facts from recommendations. For fictional pages cite their `PAGE` labels; never invent Notion URLs. Use a compact comparison only when it makes a real conflict easier to understand.

**First useful result:** the answer identifies what the sources support, why conflicting information differs, and what remains unverified. An exhaustive summary of every page is unnecessary.

## Keep exploration open

Use the neutral continuation behavior in the shared guide. Follow a new question, such as tracing a decision, opening one uncertainty, or preparing for a customer conversation. The user can finish, return to the menu, or stay with the same project without completing an exercise sequence.

Reading and answering do not authorize editing Notion. If the user wants a change, establish the exact destination and content to change before a write; confirm the saved result using the available tools. A proposed replacement paragraph remains a proposal until saved. For an export or retained recap, read [delivery](../workshop-decide/references/delivery.md). For an explicitly requested repeat check, read [recurrence](../workshop-decide/references/recurrence.md).
