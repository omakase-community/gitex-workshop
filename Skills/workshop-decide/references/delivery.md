# Results, reusable context, and recovery

## Deliver without interrupting exploration

Give a usable result in chat first. When a substantial artifact is ready, offer a file if the participant has not already requested one: an ICP or meeting action brief can become a PDF; a company list can become a spreadsheet/CSV; an email draft normally stays in chat or in the explicitly requested mailbox draft. Do not generate a report after every answer or require file export before continuing.

Use the host's available document/PDF/spreadsheet capability. A requested PDF must be a real PDF: render or inspect it before delivery. If no PDF capability is available, explain the limitation and offer an accessible HTML/text alternative or ask before installing dependencies. Do not rename another format to `.pdf`. Include readable source references, key unknowns, and the difference between proposed and completed actions. Do not include private material beyond the requested artifact.

Save participant outputs only to a local or connected destination they selected. The read-only Google Drive distribution folder contains the package and sample inputs, not participant exports. Do not upload personal email, contact data, profiles, or recovery files there. Preserve source inputs and avoid overwriting an existing output unless requested; use a distinct filename when needed.

## Optional reusable profile

A PDF is a human-readable outcome; repeatability also needs the relevant criteria and preferences. If the participant wants to remember their setup, propose a short working profile and show what it will contain before saving:

- Their business and current objective.
- Approved ICP criteria or writing preferences, when relevant.
- Chosen source/account label and bounded scope, without credentials.
- A reusable request and any open question.

Store the summary rather than a copied mailbox or raw transcript. Do not silently edit a global skill, memory, or user instructions. Saving a profile, exporting a result, and creating a scheduled task are separate choices.

## Continue in this chat

Recognize natural phrases such as "continue where we left off", "back to the workshop", or "kaldığımız yerden devam edelim". Briefly recover the last goal and pending step from available conversation context; continue without repeating intake. If the request could refer to two different goals, ask which one.

## Continue after a new chat or missing context

Before a known reload/new-chat requirement, offer this compact recap in the chat. Give it as a file only on request. Explain that it needs to be pasted or attached in the new conversation, along with the workshop folder being accessible.

    Workshop continuation
    Workflow:
    My goal:
    Source mode: own data / fictional Kivo / explicitly mixed
    Selected scope and timezone:
    Completed work and source references:
    Current result or output file:
    Next question or step:
    Connection status last observed (verify again):
    Save/write/schedule permissions: verify again before new external actions

Keep it minimal; omit private content not needed to continue. On receiving a recap, treat account status as a previous observation and verify current access. The recap is not transferable authorization to send mail or change records. If no recap/history is available, say what you lack and ask for the last result or a one-sentence reminder. Do not invent prior work or claim that a phrase alone recovers inaccessible history.
